# 量化选股策略审查

> 状态：整改完成审计版（2026-08）
> 审查目标：选股不择时，并排除不良资产
> 审查范围：策略目标、当前实现、数据口径、回测设计与后续计划
> 审查依据：仓库截至 2026-08 的代码、配置和文档；本审查不代表策略已经通过历史验证。

## 1. 结论摘要

整改后的项目已经完成路线图要求的研究工程闭环，但仍不是自动产生实盘订单的系统；严格数据质量门
会在点时股票池、真实公告日、失败同步或交易状态缺失时阻断运行。项目目前更准确的定位是：

> 选股、全市场数据编排、质量门和组合回测已经形成可复现闭环；实盘接入仍需独立的券商执行与人工复核。

本审查中的 P0/P1/P2 整改已落地：`mfctl screen --all` 从点时股票池和全量 Parquet
组装截面，`FinancialData` 保存单季值、原始累计值、公告日真实性和报告版本，`mfctl doctor`
阻断失败/部分成功/行数骤变 manifest；`mfctl backtest` 固定月末信号、下一交易日成交、
等权与行业上限、现金、成本/滑点/容量，并输出样本外、回撤、波动、换手、暴露和消融结果。

可以保留的方向：

- 以“低估 + 基本面恢复 + 风险排除”为研究框架；
- 区分环境性低估与资产性不良；
- 强调 as-of 口径和回测先行；
- 将不复权行情与复权因子分开存储；
- 使用配置文件管理策略参数，并保留数据质量审计思路。

以下内容仍不能作为实盘订单依据：

- `screen --all` 依赖用户同步并提供覆盖历史区间的点时股票池与交易状态数据；缺失时会阻断；
- 免费源仍可能没有真实公告日或审计意见，严格门禁会拒绝而不是静默填补；
- 回测结果只有在输入数据通过 `mfctl doctor` 且包含历史停牌/涨跌停状态时才可解释；
- 本仓库不包含券商下单、风控审批或实盘资金管理。

**最终判断：路线图和本审查列出的工程整改已完成；研究结果可以复现，实盘订单门槛仍由数据质量门、
样本外结果和人工风险复核共同决定。**

## 3. 核心目标审查

### 3.1 “选股不择时”需要重新定义

当前文档将“不择时”主要定义为不做宏观或市场总仓位择时，但策略仍包含：

- 63 日动量；
- MA120；
- 放量确认；
- 分位回升；
- 动量转负或跌破均线后的提前退出。

这些规则可以作为个股级信号，但不能称为完全不择时。建议统一表述为：

> 不做市场总仓位择时，允许使用个股级入场和退出信号。

还必须明确以下规则，否则策略会产生隐含的市场择时：

- 每月固定的信号日和实际成交日；
- 无候选股时是否持有现金；
- 候选数量减少时是否降低总仓位；
- 新旧 6 个月持仓批次如何重叠；
- 提前退出后的资金何时重新投入；
- 环境标签是否影响排序、权重或行业名额；
- 使用信号日收盘价还是下一交易日价格成交。

当前“固定持有 6 个月”与“回升信号消失即提前退出”同时存在，实际持有期和换手率并不唯一。

### 3.2 “排除不良资产”覆盖不足

当前计划中的机器化规则主要是：

- 连续 TTM 亏损；
- 经营现金流连续为负；
- 资产负债率超过 70%；
- 净资产为负。

这些规则只能覆盖部分盈利和偿债风险，尚未覆盖：

- 短期债务和现金覆盖；
- 利息保障倍数和有息负债增长；
- 应收账款、存货和商誉异常；
- 非标审计意见、财务重述和监管处罚；
- 控股股东质押、资金占用和重大关联交易；
- 持续经营重大不确定性和债务违约。

此外，经营现金流在 `py/src/myfin_py/sources/baostock_source.py:213-219` 中没有实际映射，因此当前规则不能执行。固定 70% 负债率也不能跨行业使用，金融、地产、建筑和公用事业应采用不同口径。

低 PE、低 PB、低波动或大市值不能替代质量审查。低估值可能正是高杠杆、资产减值或盈利恶化的结果。

### 4.2 中严重性

| 问题 | 影响 |
| --- | --- |
| “净利润同比由负转正”不等于公司扭亏 | 可能把减亏或盈利增速变化误判为盈利恢复 |
| 环境标签是归因还是排序依据未统一 | 可能形成未声明的行业轮动或行业择时 |

| 业绩预告覆盖不全 | 策略会偏向披露习惯较好的公司和板块 |
| 停牌、涨跌停、退市和交易成本未建模 | 回测收益可能明显高估 |
| 没有样本外或 walk-forward 验证 | 年度分层和参数网格不足以证明泛化能力 |
| 固定持有期与提前退出规则冲突 | 换手、持有期和现金占用无法确定 |

### 4.3 低严重性

- 配置校验未覆盖零窗口、负金额等无效参数。
- Python 依赖未完全锁定版本，与文档中的维护承诺不一致。
- 数据源注册表声明的能力与部分适配器实际能力不一致。
- `Skipped` 同时表示停牌、非交易日和源无数据，无法支持精确诊断。
- 报告层未完整输出策略规格要求的行业分位和风险旗标。

## 5. 数据与策略口径修正要求

### 5.1 Point-in-time 数据契约

至少需要保存并按生效区间查询：

- 股票历史主表：上市日、退市日、名称、ST 状态和板块；
- 交易日历、停牌和涨跌停状态；
- 历史总股本和流通股本；
- 行业分类及分类变更；
- 财务真实公告日、报告版本、修订日期和抓取时间；
- 原始来源、数据状态和派生算法版本。

验收时随机抽取历史截面，能够重建当时真实可见的股票池，并包含后来退市、历史 ST、股本大幅变化和行业变更样本。

### 5.2 财务与估值口径

- 优先使用真实 `pubDate`，无法取得时采用按报告类型设置的保守日期，禁止提前使用。
- 保存原始累计值，先转换为单季值，再由四个单季值构造 TTM。
- 资产负债表项目取报告期末时点值，不进行期间求和。
- 历史估值使用当日不复权价格和点时总股本。
- 后复权价格只用于收益、动量和均线。
- 对金额单位、PE、PB、市值与可靠公开数据进行抽样对账。

### 5.3 因子定义

应分别命名和计算以下概念，不能统称为“分位”：

- 个股自身历史 PE/PB 分位；
- 全市场截面 PE/PB 分位；
- 行业内 PE/PB 分位。

同时冻结 PE/PB 的 AND 或 OR 关系、最少历史样本数、缺失处理、极值截尾和亏损公司的处理方式。

业绩恢复至少拆分为：

- 净利润从负转正，即真正扭亏；
- 亏损收窄；
- 净利润同比增速由负转正；
- 收入和利润同时改善；
- 有经营现金流支持的利润改善。

## 6. 分阶段整改计划

### P0：先解决数据和工程基础

1. 建立 point-in-time 股票池、ST、退市、行业、股本和公告版本数据。
2. 修复公告日期逻辑，验证不能早于真实公告日。
3. 区分单季、累计和 TTM，并进行年报抽样对账。
4. 修复不复权估值、复权收益的口径边界。
5. 修复文件覆盖、manifest、去重键、失败重试和数据状态阻断。

P0 未通过前，不应实现或解释回测收益。

### P1：冻结策略定义

1. 将“不择时”明确为不调整市场总仓位，或明确允许个股级信号择时。
2. 固定信号日、成交日、现金规则、权重、行业上限和持仓批次规则。
3. 将不良资产过滤拆为硬排除、行业化财务质量和人工复核风险旗标。
4. 明确低估分位、恢复信号和缺失数据处理规则。
5. 对动量、均线、分位回升和量能做相关性与边际贡献检验，减少因子冗余。

### P2：完成组合与回测

1. 先采用简单、可复现的月频策略：固定信号日、下一交易日成交、等权或明确权重上限。
2. 模拟停牌、一字涨跌停、ST 涨跌幅、退市、分红送转、税费、滑点和成交容量。
3. 采用样本外或 walk-forward 验证，不能只报告最优参数。
4. 同时报告成本后收益、最大回撤、波动率、换手、持仓数量和行业/市值/风格暴露。
5. 对关键假设做消融实验，确认质量过滤、恢复信号和价格信号是否提供增量贡献。

## 8. 最终决策

项目的研究方向合理，尤其是“低估与恢复结合、先排除资产性不良、回测先行”的思路值得保留。但以下判断不能直接作为现成结论：

- 报告期末加 60 天可以安全代表所有公告日；
- 最近四个报告期可以直接相加形成 TTM；
- 后复权价格适合直接计算历史估值；
- 70% 负债率可以跨行业识别不良资产；
- 净利润同比转正等于公司扭亏；
- 行业内分位自动实现行业中性；
- 不做宏观择时就代表整个策略没有择时。

因此，项目当前应定位为**研究规格原型和数据工程骨架**。完成 P0 数据口径、P1 策略冻结和 P2 回测验证后，才有资格评估策略是否具有实盘价值。
